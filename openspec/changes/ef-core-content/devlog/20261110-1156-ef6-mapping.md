# Decision: "Coming from Entity Framework 6", after the concepts

<!-- Section: 3 · Before 3.1 · Base: be7c211 -->

Before writing the page, I found that the plan clashed with `site/README.md`. The README said:
"old-to-new mappings belong on the _Coming from .NET 3.5_ page". Design D1 and the spec put a "Coming
from Entity Framework 3.5/4" table first on the EF Core page.

## Emmz's answers (2026-11-10)

- "i think it should probably say 'Coming from Entity Framework 6'".
- She then chose, from a preview, **the same table at the end**: after the concepts (Change
  tracking), before Pitfalls.

## What changed

- **The spec:** "EF Core page maps Entity Framework 3.5/4 habits" is now "… Entity Framework 6
  habits". It lists the EDMX designer, lazy loading on by default, `ObjectContext` or a hand-made
  context, EF6 migrations, the `NotSupportedException` for LINQ EF6 can't translate, and
  `System.Data.Entity`. Its scenarios are the designer and "where lazy loading went".
- **A factual fix, raised in the question:** the first plan's "silent client-side evaluation" row
  was wrong. EF 3.5/4/6 threw `NotSupportedException` for LINQ they couldn't translate. Silent
  client evaluation was EF Core 1–2. The row is gone, and the querying requirement no longer says
  "replaced EF 3.5's silent client evaluation".
- **Design D1** (the new order, with "Revised in §3") and the proposal's Why and What Changes.
- **`site/README.md`:** the mapping rule gains one exception, a short "Coming from …" table at the
  end of the concepts when a topic replaces a library the readers used.

`openspec validate ef-core-content --strict` passes.
