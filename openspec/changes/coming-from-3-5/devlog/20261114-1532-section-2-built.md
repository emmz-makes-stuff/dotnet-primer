## Verified

- Starter: 5 fail, 2 pass (`BasketKeepsItsItems` and `EmptyBasketCantBeCheckedOut`, the

- Scratch copies (scratchpad `ex15/`):
  - (a) the Starter completed with the Solution's code: 7/7;
  - (b) without TODO 3: only `BasketFollowsTheShopperToTheOtherServer` fails;
  - (e) TODO 3 half done (application name, no keys folder): the same test fails, with "there's no
    key in the folder DataProtection:KeysPath names": the second assert caught keys shared through
    `~/.aspnet`;
  - (c) without TODO 4 (order kept in session, basket not emptied): only the two TODO 4 tests fail;
  - (d) TODO 1 done but TODO 2's stubs left: all 7 fail, every one a 500.

## Decisions

- **TODOs 1 and 2 build on each other**, so "leave one out, only its tests fail" holds for TODOs 3
  and 4, not for 2 without 1. TODO 1 is "keep the basket in session", which can't be done without
  some way to store an object. That's acceptable: the Starter's failures point at TODO 1 first. For
  (d), `Expect.Status` now adds the exception from a 500's body (the test host runs in
  Development), so the failure reads "The app threw System.NotImplementedException: TODO 2: read
  the value as a string, and deserialize it from JSON."
- **The cross-server test checks the keys folder too.** Without it, setting only the application
  name passes on a machine with a writable `~/.aspnet` (this Mac, CI), because both copies use the
  user-profile key ring, which two real servers wouldn't share.
- **Page path in messages:** `/aspnet-core/session-and-state/` (D1). §3 must use that slug.
- Private constants and static fields take the `_` prefix (IDE1006 in `samples-format`).
