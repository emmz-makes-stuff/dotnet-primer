## 3.1

- `samples/benchmarks/Benchmarks/` (`Benchmarks.csproj`, `Program.cs` with `BenchmarkSwitcher`)
  is in `Primer.slnx` only. Five classes in `Primer.Benchmarks`, each with `[MemoryDiagnoser]` and
  a `Baseline = true` method, and inputs in instance fields set in `[GlobalSetup]` (the probe's
  plan): `OrderLineParsing`, `StringBuilding`, `Buffers` (`[Params(1_024, 100_000)]`, which puts
  100 000 on the LOH), `Json` (an internal `OrderJsonContext`), and `Lookups`.
- **No analyzer rule relaxed.** The namespace and the instance fields were enough: no CA1822 or
  CA1050 fired, so there's no `.editorconfig` or `NoWarn`.
- **Gotcha:** an XML comment can't contain `--`, so the run command (`-- --filter '*'`) lives in
  `Program.cs`, not in the `.csproj` comment (MSB4025).
- `make samples-test` never mentions the benchmarks (grep count 0), and gives `SAMPLES_TEST_EXIT:0`.

it ("about 3× faster, no allocation"), not quote 10.24 ns as exact.

**For §4 to settle with Emmz before the page claims it:** `FrozenDictionary` was only 2% faster
than `Dictionary` (0.98) for 100 short `SKU-n` keys on .NET 10. The page can't sell it as a big
win. I haven't tuned the benchmark to get a better number. The options are to state the small
gain honestly ("measure: here it barely helped"), to change the example (other keys or sizes,
re-measured), or to drop the claim. That's a product call, so ask when 4.2 gets to it.
