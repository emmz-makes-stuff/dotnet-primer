## 7.3: the checker is more robust

- `TestRun.Timeout` is 10 minutes per run (build and tests). I chose 10, not 5, because a first run
  also restores packages.
- When it runs out, the checker kills the whole process tree and reports `RunResult.TimedOut` with
  a hint: "A test is probably waiting for something that never happens … Give that wait a time
  limit". It handles a timeout on the correct-API run and on the bug runs.
- **I proved it** in a scratch copy, with the timeout cut to 20 s and a test that awaits
  `Task.Delay(Infinite)`. The checker stopped after `real 21.37` s, and no test host process was
  left.
- I dropped my first hint, "pass the test's CancellationToken". That token doesn't end a hang
  unless the test has a timeout, so the advice was wrong.
- An unexpected exit code on a bug run now prints "stopped without a result (exit code n). A test
  may have crashed the test run, or the exercise may be at fault", followed by the run's output. It
  no longer says the exercise is at fault.
