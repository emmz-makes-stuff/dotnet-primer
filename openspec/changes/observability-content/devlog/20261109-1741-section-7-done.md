`kestrel.connection.duration` (s) and `kestrel.queued_connections` all appear. They report on
connection events, so §1's single keep-alive connection gave them nothing to report. The page says

**The page's `dnx dotnet-counters monitor` command** works as written (no `--`, no prompt):
- With all five providers, the output shows `[Microsoft.AspNetCore.Hosting]`, `[…Kestrel]`,
  `[System.Net.Http]` and `[System.Runtime]`, but `[Orders]` falls off the one-screen display.

  percentiles, and the Kestrel instruments.
- The page now tells readers to list a few providers at a time.

**Gotchas, now on the page:**
- **Only one `dotnet-counters` session per process.** Running `collect` and `monitor` together
  failed: "Another metrics collection session is already in progress for the target process.
  Concurrent sessions are not supported."
- **Without `--counters`,** only `[System.Runtime]` is shown (verified).
- **`dnx` swallows options it owns.** `dnx dotnet-counters monitor --help` printed **dnx's** help.
  `dnx dotnet-counters -- monitor --help` gives the tool's, which is why §1 used `--`. `-n`,
  `--counters`, `--format`, `--output` and `--duration` pass through fine without it.

**`AddAspNetCoreInstrumentation()` includes Kestrel:** the 1.20.2 `net10.0` DLL names the meters
Hosting, Server.Kestrel, Routing, Diagnostics, RateLimiting, Http.Connections, Authentication and
Authorization. The page says it subscribes to ASP.NET Core's meters, Kestrel's included.
