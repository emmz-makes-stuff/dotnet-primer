  `Directory.Packages.props` and `global.json`. An awk extraction diffed against the files reported

  under `samples/` is explained. I enumerated them, and the six web csprojs are identical and empty.
- **`init` and `env set none` output** is copied from Learn, with its placeholders. It was not run
  (D2).
- **The `global.json` paragraph** quotes the observed bare-install line, and links Learn's
  "Repository SDK requirements" page. That page documents the same `latestFeature` → `10.0` mapping
  the probe saw. It explains why the setup check names `10.0.4xx`.
- **LTS/STS** follows Learn's releases-and-support page: LTS at least 3 years, STS 2 years (since
  .NET 9). .NET 10 is supported until November 2028.

## Verified

- In the repo, `dotnet --version` gives 10.0.403. Outside it, it gives 11.0.100-rc.1 (the
  wrong-folder pitfall).
- A missing-SDK `global.json` (10.0.999, `disable`) gives "A compatible .NET SDK was not found",
  then Requested SDK version, the global.json path and the installed SDKs, exit 155.
- A `Version` on a `PackageReference` under CPM gives `error NU1008`.
- `dotnetup dotnet -- --version` gives 10.0.403.
- **Setup check (2.2):** a fresh `git clone` from GitHub (main `b0ee30f`), then
  `dotnetup sdk install 10.0.4xx` into the isolated root, with PATH/DOTNET_ROOT on that root only.
  `dotnet --version` gave 10.0.403, and `dotnet test --project
  samples/exercises/01-configuration/Solution.Tests` gave `Test run summary: Passed!`, 2 succeeded,
  exit 0.
- **Link check:** all 12 Learn links OK. The in-page anchors `#check-your-setup`,
  `#pin-the-sdk-with-globaljson` and `#the-sdk-style-project-file` exist in `dist`, and the built
  page has no "Coming soon".
