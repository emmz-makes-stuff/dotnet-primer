## Rejected, with evidence

- **"Try it yourself" on `localhost:5000` reaches AirPlay on a Mac:** measured with the Starter
  running. ControlCenter holds `*:5000`, the app holds `127.0.0.1:5000` and `[::1]:5000`, and
  `localhost`, `[::1]` and `127.0.0.1` all answered with `Server: Kestrel` (see `2020`).
- **The Lambda snippet needs `using Amazon.Lambda.AspNetCoreServer.Hosting;`:** it compiled as
  shown (§3). `LambdaEventSource` and `AddAWSLambdaHosting` are in
  `Microsoft.Extensions.DependencyInjection` (the package's XML docs), which implicit usings bring
  in.
- **A JSON secret's keys may not land as `ConnectionStrings:Orders`:** confirmed from the provider's
  source on `main`. A `/aws/reference/secretsmanager/…` path gets `JsonParameterProcessor`. Its
  key prefix is `GetKey(parameter, path)`, which strips the path from the name, and the name is
  the path, so the prefix is empty. `ParseJsonParameter("", value)` then adds the JSON's own keys.
- **`ReadinessFailsWhileShuttingDown` races with TODOs 1–3 done and the Starter's 1 s timeout:** it
  didn't reproduce in 31 runs. The poll loop starts its clock after `BeginStop`, so the 1 s timeout,
  measured from slightly earlier, fires after the last poll. The margin is thin, but left as is.

- **7.1:** `healthCheck` is out of `task-definition.json`, so the JSON is safe with the chiseled
  image. A `healthCheck` fragment follows it, titled "needs a shell and curl in the image", and the
  bullet says the task definition above leaves it out. Parse-checked again, sandboxed with no
  credentials: the task definition alone, and with the fragment merged into the container
  definition, both reach `Unable to locate credentials`, so both passed parameter validation.
- **7.2:** the Shopfront snippet now builds the app and calls `app.MapDefaultEndpoints();`, with a
  comment that the AppHost's `WithHttpHealthCheck("/health")` asks for `/health`. Compiled against
  a stub with the template's signature, `MapDefaultEndpoints(this WebApplication app)`.
- **7.3:** the IAM permissions are named. `ssm:GetParametersByPath` for the path. For the secret's
  reference path, one `GetParameter` call (linked to the provider's `SystemsManagerProcessor.cs`,
  which gave 200), so `ssm:GetParameter`, and `secretsmanager:GetSecretValue`, because Parameter
  Store "functions as a pass-through service", and a reference fails without permission to access
  the secret (AWS's integration page).
- **7.4:** Logging, Tracing and Metrics now say "The Orchestration & AWS page covers running the app
  itself on ECS and EKS. For the collector, follow the links above." Their main-spec requirement,
  linking to that page for deployment, still holds.
- **7.5:** `Expect.OrderInProgressAsync` uses `Task.WhenAny`. A POST that answers without starting
  an order reports its status at once, a faulted one reports its error, and a timeout reports as
