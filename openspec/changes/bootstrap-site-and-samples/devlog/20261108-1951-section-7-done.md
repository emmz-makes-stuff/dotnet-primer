## Layout decisions

**Project names** are `Configuration.{Starter,Solution}[.Tests].csproj`, not a bare `Starter.csproj`.
Future exercises will sit in the same `Primer.slnx`, and unique project and assembly names avoid
clashes there. The folder names still match D1 and the site's
`dotnet test --project samples/exercises/01-configuration/Starter.Tests` command.

**Shared tests:**

- The shared test source is `exercises/01-configuration/tests/GreetingEndpointTests.cs`, pulled into
  both test projects with `<Compile Include="../tests/**/*.cs" />`.
- Both apps declare `public partial class Program;` explicitly. It produced no analyzer warning.
- The tests use `Assert.True(cond, message)`, because xUnit's `Assert.Equal` has no message overload,
  and the spec wants failure messages that point at the missing behaviour.
- They pass `TestContext.Current.CancellationToken`, which keeps the xUnit1051 analyzer quiet.

**The override test** uses `WithWebHostBuilder` with `AddInMemoryCollection`. That stands in for a
later configuration layer, such as the `Greeting__Message` environment variable. It avoids mutating
real process environment variables, which would race with xUnit's parallel test classes.
