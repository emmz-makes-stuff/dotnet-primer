## What landed

- **2.1:** `samples/exercises/08-grpc/` has `Grpc.Starter`, `Grpc.Solution`, the shared `tests/`, and
  `Grpc.{Starter,Solution}.Tests`. All four are in `Primer.slnx`; the Solution and its tests are in
  `Primer.Solutions.slnx`. The test projects build their client from `tests/Protos/orders.proto`
  (`GrpcServices="Client"`, linked as `Protos/orders.proto`).
- **2.2, the Solution:** the full contract, `Orders.cs` (`StoredOrder`, `OrderStore`,
  `OrderValidation.Problems`, `IOrderTracker`, `SimulatedOrderTracker`), `OrdersService` with the
  three RPCs, and `Program.cs`. `appsettings.json` sets `Kestrel:EndpointDefaults:Protocols` to
  `Http2`, so `dotnet run` would serve gRPC.
  - **Names:** the app code is in `GrpcOrders`, the server's contract in `GrpcOrders.Contract`, the
    tests' contract in `GrpcOrders.Tests.Contract`. The stored types are `StoredOrder`/`StoredLine`,
    so a bare `Order` inside `namespace GrpcOrders…` can't resolve to the wrong type.
  - **The two contracts match:** `diff` with the `csharp_namespace` line removed is empty. The header
    comment is written to be true in both files.
- **2.3, the tests:** 12 (6 facts, 6 theory cases), in `OrdersServiceTests` and `OrdersApp`. Each
  test starts its own in-memory app. The `Hints` helper turns `Unimplemented` into the right TODO,
  keyed on the details found in 1.1.
- **2.4, the Starter:** TODOs 1–5. `PlaceOrder` works but doesn't validate (TODO 2). `GetOrder` and
  `TrackOrder` aren't overridden. The `.proto` has no `TrackOrder` (TODO 4). `Orders.cs` is
  identical to the Solution's (`cmp`).

The changes from design D4 are under "Revised in §2" there: no `status` on `Order`, the Starter's
"works, but badly" `PlaceOrder`, its one-parameter constructor, the cancel test, the later server
deadline, and the field-number check.
