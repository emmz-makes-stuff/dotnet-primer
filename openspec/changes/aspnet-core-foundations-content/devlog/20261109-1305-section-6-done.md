## Risk resolved: does `Response.Clear()` wipe headers? (task 6.3)

Yes. I ran four variants in the scratch copy (`scratchpad/ex03/`):

| Variant | Result |
|---|---|
| Completed (`OnStarting`, registered first) | 4/4 pass |
| Header set **directly**, registered **first** (outside the exception handler) | only `ErrorResponseStillHasCorrelationId` fails |
| Header set directly, registered **inside** the exception handler | the same single failure |
| `OnStarting`, registered **after** maintenance | only `ShortCircuitedResponseStillHasCorrelationId` fails |

So the exception handler clears headers whatever the order. **Order** fixes the short-circuit case, and
only **`OnStarting`** fixes the error case. The Pitfalls wording planned in D7 stands unchanged. The
starter's red run fails 4/4, with the guiding messages.
