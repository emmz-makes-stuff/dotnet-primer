## Decisions (also in design D4, "Revised in §2" and "Added in §2")

- **The request:** `{ customerEmail, items: [{ sku, quantity, unitPrice }] }`, and the server
  computes the total. This is a small change from "the same request as 04–06".
- **`ToTable("OrderLines")`:** reviewing the first migration showed that the table was named after
  the class, `OrderLine`. That makes a good "review your migration" example for the page.
- **`[FromServices]` in the Starter only,** so an unregistered context doesn't stop the app starting.
- **`.editorconfig` gained `[**/Migrations/*.cs] generated_code = true`.** EF's generated
  `InitialCreate.cs` broke the build with IDE0161 under `EnforceCodeStyleInBuild`, and would have
  done the same for a reader's own migration.
- **Private fields have a `_` prefix** (IDE1006 in `dotnet format`), which matches the repo's
  existing rule.

## Gotchas for §3 (the page)

- **`migrations remove` connects to the database,** and fails without a connection string ("The
  ConnectionString property has not been initialized"). `--force` skips the check. This goes in the
  page's Pitfalls and the cheatsheet.
- **EF Core 10's migration lock** (from the probe): don't claim that concurrent startup migrations
  corrupt the schema.
- **The convention-based relationship** (Lines/OrderId) is found without configuration. The page
  can say that conventions found it, and that the fluent API makes it explicit.
- **"From the exercise" snippets:** copy them from `Solution/Program.cs` and
  `Solution/OrdersDbContext.cs`.
