### Two gotchas for the page

- **SqlClient needs ICU.** The same API on plain `aspnet:10.0-noble-chiseled` dies with `Unhandled
  exception. System.NotSupportedException: Globalization Invariant Mode is not supported.` So an app
  that uses SQL Server goes on `-noble-chiseled-extra`. This is the page's example of choosing
  `-extra`, and a Pitfall.
- **`localhost:8080` reached another process on this Mac** (an unrelated Vite dev server on IPv6
  `::1`). `127.0.0.1:8080` reached the container. The page tells readers to change the host side of
  `ports` (`"5080:8080"`) if 8080 is taken, and not to kill whatever holds it.

## Local registry

`registry:3` is current (`registry:2` still pulls). **The page and D7 use `registry:3`.** On port
5001 (5000 is ControlCenter's here):

- `docker tag … localhost:5001/probe:1.0.0` and `docker push` gave `1.0.0: digest:
  sha256:8cba0498…94d2 size: 1575`. After `docker image rm`, `docker pull` gave `Status: Downloaded

  -p:ContainerRepository=probe-sdk -p:ContainerImageTags='"1.0.0;latest"'` printed:

  ```
    Building image 'probe-sdk' with tags '1.0.0,latest' on top of base image 'mcr.microsoft.com/dotnet/aspnet:10.0-noble-chiseled'.
    Pushed image 'probe-sdk:1.0.0, latest' to registry 'localhost:5001'.
  ```

  It went over plain HTTP with no extra setting (the SDK allows `localhost`), and the registry
  listed `probe` and `probe-sdk`. `ContainerImageTags` needs the inner quotes in a shell, because
  of the `;`.

## ECR (AWS docs, fetched 2026-11-11, not run)

From "Pushing a Docker image to an Amazon ECR private repository" and "Private registry
authentication":
- `aws ecr get-login-password --region <region> | docker login --username AWS --password-stdin
  <aws_account_id>.dkr.ecr.<region>.amazonaws.com`;
- the token lasts **12 hours**, for each registry;
- the repository must exist before the push (`aws ecr create-repository`), unless a repository
  creation template creates it on push;
- then `docker tag <image> <account>.dkr.ecr.<region>.amazonaws.com/<repo>:<tag>` and `docker push`.
  With `dotnet publish`, use `ContainerRegistry=<account>.dkr.ecr.<region>.amazonaws.com`, after the
  same `docker login`;
- the alternative is the Amazon ECR credential helper, which doesn't support MFA.

That `dotnet publish` uses `docker login`'s stored credentials is documented SDK behaviour, but not
measured with ECR. The page says the ECR steps weren't run.
