## Facts the page can state, with their source

- **ECS deregisters a task from its target group before it sends the stop signal.** The lifecycle
  page has DEACTIVATING ("the target group deregistration occurs during this state") and then
  STOPPING, where the agent sends the image's `STOPSIGNAL`, "`SIGTERM` by default. Then it will send
  a `SIGKILL` after waiting the `StopTimeout` duration set in the task definition". This answers
  `1900`'s question: **on ECS behind an ALB, the load balancer drains first, so the app's drain
  delay matters most elsewhere** (EKS, or any platform that signals and deregisters together). The
  page should say so, and keep the delay short.
- **`stopTimeout`:** "If the parameter isn't specified, then the default value of 30 seconds is
  used. The maximum value is 120 seconds." (Fargate platform version 1.3.0 or later.) So: drain
  delay + longest request < `ShutdownTimeout` < `stopTimeout` (default 30 s, max 120 s on Fargate),
  and `docker stop` locally gives 10 s (measured in 1.2).
- **ALB deregistration delay:** "By default, Elastic Load Balancing waits 300 seconds before
  completing the deregistration process", and it completes at once if the target has no in-flight
  requests. The attribute is `deregistration_delay.timeout_seconds`. "If a deregistering target
  terminates the connection before the deregistration delay elapses, the client receives a 500-level
  error response."
- **ALB health check defaults** (target type `ip`, which Fargate uses): path `/`, interval 30 s
  (range 5–300), timeout 5 s (range 2–120), healthy threshold 5 (range 2–10), unhealthy threshold 2
  (range 2–10), matcher `200`. **Point it at `/health/ready`.**
- **The container `healthCheck`:** `command` is a string array starting `CMD` or `CMD-SHELL`; the
  docs' example is `[ "CMD-SHELL", "curl -f http://localhost/ || exit 1" ]`. Defaults: interval 30 s
  (5–300), timeout 5 s (2–60), retries 3 (1–10), and an optional `startPeriod`. "The health check
  commands run on the container. Therefore you must include the commands in the container image."
  So a chiseled image, with no shell and no `curl`, can't run that example (`CMD-SHELL` needs a
  shell, too). Also: "Amazon ECS doesn't monitor Docker health checks that are embedded in a
  container image but aren't specified in the container definition."
- **Secrets:** `secrets: [{ "name": …, "valueFrom": <Secrets Manager ARN or SSM parameter> }]`
  becomes an environment variable. The **execution role** reads them: `ssm:GetParameters`,
  `secretsmanager:GetSecretValue` and, for a customer managed key, `kms:Decrypt`. The **task role**
  is what the app's own code uses ("This role allows your application code (running in the
  container) to use other AWS services"), and those permissions "aren't accessed by the Amazon ECS
  container and Fargate agents".
- **EKS:** "$0.10 per cluster per hour" in standard support, and "$0.60 per cluster per hour" in
  extended support (which runs for 12 months after standard support ends). The AWS Load Balancer
  Controller makes an ALB for a Kubernetes `Ingress` (and, from 2.14.0, a `Gateway`) and an NLB
  for a `Service` of type `LoadBalancer`. Pod Identity: "you associate an IAM role with a
  Kubernetes service account and configure your Pods to use the service account", and EKS sets
  environment variables that "configure the AWS SDKs … to use the EKS Pod Identity credentials".
- **Lambda:**
  - The function timeout is "900 seconds (15 minutes)".
  - There's a managed **`dotnet10`** runtime (Amazon Linux 2023, deprecation Nov 14, 2028).
    `dotnet8`'s deprecation is Nov 10, 2026, which is the day before this probe.
  - The ASP.NET page installs `dotnet tool install -g Amazon.Lambda.Tools` and **deploys with
    `dotnet lambda deploy-serverless`** (CloudFormation), from the
    `dotnet new serverless.AspNetCoreMinimalAPI` template. **D8 says `dotnet lambda
    deploy-function`; the page will use the docs' `deploy-serverless`.** Not syntax-checked,
    because `Amazon.Lambda.Tools` isn't installed (D8 already says so).
  - Native AOT "can reduce the cold start time", but it must be compiled on Amazon Linux 2023. The
    AOT page still talks about the .NET 8 runtime.
- **Secrets Manager through Parameter Store:** the name "must begin with the following reserved
  path: `/aws/reference/secretsmanager/`". The provider's README shows
  `builder.AddSystemsManager("/aws/reference/secretsmanager/SomeSecret")`, and says it uses
  `JsonParameterProcessor` to load a secret's key/value pairs. Under a path, the prefix is stripped,
  and `/` becomes `:` (`/my-application/api/key` → `api:key`). The credentials need
  `ssm:GetParametersByPath`, plus access to the secret when one is referenced.
