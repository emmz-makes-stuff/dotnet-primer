# Probe (1.1)

<!-- Section: 1 · Task: 1.1 · Base: 987885a -->

The probe projects are in the session scratchpad (`grpc-probe/`): a `dotnet new web` server with
`Grpc.AspNetCore` 2.85.0, a console client, and an xUnit v3 test project. They used SDK 10.0.403
through the repo's `global.json`, and ran unsandboxed (NuGet and the local ports).

## Findings

- **Restore is clean.** `Grpc.AspNetCore`, `Grpc.Net.Client`, `Grpc.Tools` 2.85.0 and
  `Google.Protobuf` 3.36.2 built with warnings as errors and gave no NU190x audit warnings. No
  transitive pin is needed.
- **Design D3 works.** The test project generates a client from a copy of the `.proto` whose
  `option csharp_namespace` differs (`Probe.Tests.Contract`, against the server's `Probe.Server`). It
  also references the server project. The two sets of generated types don't clash, and the calls
  go through `factory.Server.CreateHandler()` with no port or HTTP/2 setup.
- **Statuses the tests' hints can tell apart:**
  - **nothing mapped** (`AddGrpc` but no `MapGrpcService`): `Unimplemented`, detail
    `Bad gRPC response. HTTP status code: 404`;
  - **an RPC missing from the server's contract:** `Unimplemented`, detail
    `Method is unimplemented.`;
  - **a whole service missing:** `Unimplemented`, detail `Service is unimplemented.`.

  So the "not mapped" hint keys on the 404 detail, and the "add `TrackOrder` to the `.proto`" hint
  on `Method is unimplemented.`.
- **Deadline on a server stream:** with a 1,500 ms deadline and 1 s between updates, the client got
  `DeadlineExceeded` with an empty detail after 1,520 ms, having read one update (`Placed`). The
  server's `context.CancellationToken` was cancelled at the same moment (`Task.Delay` threw), and it
  had produced 1 update. Cancellation reaches the service under the test server, so D4's deadline
  test is sound.
- **HTTP/2 on Kestrel (D5),** with endpoints set in `appsettings.json` under `Kestrel:Endpoints`:
  - `"Protocols": "Http2"` on `http://localhost:5287`: the console client's unary call works, and an
    unknown id gives `NotFound` with the service's detail.
  - `"Protocols": "Http1"`, **and also the default `"Http1AndHttp2"`**, on a plain-HTTP URL: the
    client fails with `StatusCode=Internal`, detail
    `Error starting gRPC call. HttpRequestException: The HTTP/2 server closed the connection. HTTP/2 error code 'HTTP_1_1_REQUIRED' (0xd). (HttpProtocolError)`.
    Without TLS, Kestrel can't negotiate HTTP/2, so the default endpoint of `dotnet new web` won't
    serve gRPC. This is the page's main Pitfall.
- **xUnit1051 is an error** under warnings as errors: every gRPC call in the tests that takes a
  `CancellationToken` must pass `TestContext.Current.CancellationToken`. The probe turned the rule
  off; the exercise tests must not.

## Gotchas hit

- **Port 5180 was taken** by a `node` process on this Mac (left alone). The probe used 5287 and 5288.
  The page's example port must be one that the `dotnet new` templates don't pick at random either;
  any fixed port works, and the page says to change it if it's in use.
- **A stray `python3 -` in a shell command hangs** it on stdin (the second time in two sessions).
  It was stopped with TaskStop, and the steps were rerun.
