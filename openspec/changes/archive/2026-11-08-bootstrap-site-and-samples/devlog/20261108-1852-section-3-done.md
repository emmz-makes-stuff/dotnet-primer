## What landed

- **3.1 `learn` schema.** It uses Zod 4's `z.url({ protocol: /^https$/, hostname: /^learn\.microsoft\.com$/ })`
  rather than D4's `z.string().url().startsWith(...)`. The reasons:
  - `astro check` flags `.url()` as deprecated (ts6385);
  - matching the hostname also rejects lookalike hosts.

  Verified to fail the build, naming the page, for:
  - a missing `learn` field ("learn: Required");
  - `https://example.com`;
  - `http://learn.microsoft.com`;
  - `https://learn.microsoft.com.evil.io`.
- **3.2 `MarkdownContent` override.** It renders the stock component, then an `<aside>` titled
  "On Microsoft Learn".
  - **Gotcha:** Starlight's built-in **404** route uses a synthetic entry that skips our schema, so
    `learn` is undefined there. That crashed the build, and the fix is `?? []`.
  - So 404 has no Learn block, and **section 5's tests must exclude `404.html`**, as D7 already
    says.
- **3.3 `EditLink` override.** It renders the stock edit link plus `<a data-report-problem>`.
  - The `data-report-problem` attribute is the hook for the section 5 tests.
  - Import `Icon` from `@astrojs/starlight/components`. The `user-components/` path isn't exported.
  - Verified on a scratch nested page, the splash index and 404: each gets a correct decoded
    title/body with the full `https://dotnet-primer.emmz.dev/...` URL. The D5 `Footer` fallback is
    **not** needed.
  - 404 also gets a Report link, with a `/404/` URL. That's harmless.
- **3.4 `site/README.md` authoring guide.** It still needs a run-through: section 4 follows it to add
  a page.
