## `site.yml`

- **Triggers:** push to main, PR to main, and `workflow_dispatch`.
- **`gates` job:**
  1. Install with `npm ci --prefix site` (Node from `site/.nvmrc`, npm cache keyed on the lockfile).
  2. Run build, lint, format and test with the same commands as the Makefile.
  3. On non-PR runs from `main` only, run `upload-pages-artifact` on `site/dist`.
- **`deploy` job:** `needs: gates`, with the same `if`, using environment `github-pages`. It has
  `pages: write` and `id-token: write` scoped to that job only. Workflow-level permissions are
  `contents: read`.

**Deviation from D10:** `concurrency.group` is `pages-${{ github.ref }}` rather than a single `pages`
group. A single group would make PR gate runs queue behind deploys from `main`. Deploys from `main`
still serialise, and `cancel-in-progress` is `false`, as D10 specifies.

## `samples.yml`

- **Path filter:** `samples/**`, `global.json`, `.editorconfig` (it drives `dotnet format` and the
  code-style build) and the workflow file itself.
- **Setup:** `setup-dotnet@v6` with `global-json-file: global.json`.
- **Gates:** the three samples gates, using the same commands as the Makefile.
- It is a separate workflow, so a samples failure never blocks a site deploy, as D10 requires.
