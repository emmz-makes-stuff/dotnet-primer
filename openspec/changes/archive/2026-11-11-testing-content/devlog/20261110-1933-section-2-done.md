## Design revisions (D3, written in)

- `CancelPolicy` is a **static** `CanCancel(Order, TimeProvider)`. Bug 3's copy ignores the
  parameter, and as a primary-constructor class, the unread parameter would be CS9113, an error.
- **Bug 2 releases `[]`** instead of not calling `ReleaseAsync`. A removed `await` would be CS1998.
  So a test that only checks "was called" misses it, and TODO 2 says to check what the warehouse was
  told. The spec's "no longer tells the warehouse to release its stock" still holds: no stock goes
  back.
- Cancelling an already cancelled order is a `409`, like a closed window.
- The single-changed-line rule for bug files is written into D3. The checker's drift check (3.1)
  relies on it: the same line count, and only the marked line differs.

## Gotchas

- **Running the App by hand:**
  - `dotnet run --project App`, started in the background or detached with `( … &)`, printed nothing
    and was killed (exit 137).
  - What works: `dotnet build App`, then `(ASPNETCORE_URLS=http://localhost:5091 dotnet
    bin/Debug/net10.0/Testing.App.dll > log &)` from `App/`, unsandboxed.
  - Call it with `node -e` and `fetch`, because `curl` is blocked by the context-mode hook.
  - Stop it by its pid, after a `ps` check.
- **xUnit1051 is an error:** every call that takes a `CancellationToken` must pass
  `TestContext.Current.CancellationToken`, including NSubstitute's `DidNotReceiveWithAnyArgs()`
  placeholders. The Starter's TODO comments don't mention this yet; 3.2 or 4.2 should (the
  analyzer message is clear, but a hint helps).
- `IWebHostBuilder` needs `using Microsoft.AspNetCore.Hosting;` in a test project.
- The bug files are outside the App's default compile, so the format gate doesn't check them.
  That's accepted, per the design's risks.
